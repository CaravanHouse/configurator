# Конфигуратор проекта для сайта CaravanHouse

[![CI](https://github.com/CaravanHouse/configurator/actions/workflows/ci.yml/badge.svg)](https://github.com/CaravanHouse/configurator/actions/workflows/ci.yml)

Клиент отмечает, что ему нужно (бот, сайт, мини-апп и функции), и сразу видит примерную смету и срок. Заявка прилетает вам в Telegram с кнопками статуса.

**Что показывает клиенту:** сайт + бот в связке. Это ещё и рабочий инструмент: он собирает заявки.

## Важно: цены
Все цены и сроки в `shared/pricing.ts` — **примерные заглушки**. Поправьте числа под ваш прайс: сайт и сервер считают смету из этого одного файла.

## Что внутри
- Смета пересчитывается сразу: скидка 10% за комплекс, наценка за срочность, диапазон «от и до»
- Сумму считает сервер заново, цифрам из браузера не верит
- Защита от спама: скрытое поле-ловушка и лимит 5 заявок в час с одного IP
- Заявка приходит в Telegram: кнопки «Взять в работу / Отклонить / Готово», видно, кто взял
- `/leads` показывает открытые заявки, `/id` помогает узнать id чата для `ADMIN_CHAT_ID`

## Запуск
```bash
npm install
cp .env.example .env     # BOT_TOKEN и ADMIN_CHAT_ID
npm run build
npm start
```
Без токена сервер работает, заявки сохраняются в `data/leads.json`. Тесты: `npm test`.

## Куда приходят заявки
Если заданы `ORDER_BOT_URL` и `LEAD_SECRET`, заявка уходит в бота заказов @CaravanHousebot (репозиторий `caravanhouse-order-bot`) и появляется в группе «Заказы» с голосованием команды — как заявки из Telegram и с сайта. Поля «Бюджет» и «Сроки» заполняются вилкой цены и сроком из калькулятора. Если бот заказов не ответил, срабатывает запасной канал: собственный бот конфигуратора присылает заявку в `ADMIN_CHAT_ID`. Сама заявка в любом случае сохраняется в `leads.json`.

## Деплой на Railway
Деплойте конфигуратор **первым**: его адрес нужен `quiz-bot` для кнопки «Посчитать смету».

1. **New Project → Deploy from GitHub** → этот репозиторий. Команды сборки и запуска, health check (`/health`) и автоперезапуск уже описаны в `railway.json`.
2. **Подключите Volume** с путём `/data`. Без него заявки стираются при каждом деплое.
3. **Variables:** `BOT_TOKEN`, `ADMIN_CHAT_ID` (напишите боту `/id`), `DATA_DIR=/data`. `PORT` Railway задаёт сам.
4. **Settings → Networking → Generate Domain**: получите публичный адрес сайта.
5. Оставьте **1 реплику**: данные лежат в JSON-файле, несколько копий сервера затрут друг друга.

`TRUST_PROXY` на Railway включается автоматически, без него у всех посетителей был бы один IP прокси, и лимит заявок блокировал бы всех сразу. Отключить можно через `TRUST_PROXY=0`. Для каждого проекта нужен **свой бот** в @BotFather: один токен в двух проектах даёт ошибку 409 Conflict.

## Данные
Заявки хранятся в JSON-файлах в папке `DATA_DIR` (по умолчанию `./data`). Лимит заявок по IP хранится в памяти и обнуляется при перезапуске. При большой нагрузке переходите на PostgreSQL.
